# tiancode v0.0.25

Shell 治理三件套（默认超时可配 / 快捷命令 / 输出有界）+ 白名单加固 + 双开守卫。

## 工作区 Shell 治理

- **可配 shell 默认超时**：大仓库 `go build` / `npm install` 不再被 120s 掐——工作区设置可配默认超时，模型仍可逐条覆盖（硬顶 600s）
- **快捷命令**：工作区三槽 build/test/run 一键跑；执行复用命令行同一条链（同一 shell 工具、同一超时、同一审批闸门），不新增执行能力
- **前台输出有界（64KB）**：verbose 构建/测试动辄数 MB，超限做头尾保留截断（UTF-8 边界安全），带唯一截断标记与出路提示

## 审批白名单加固

- 命中判定收紧为纯函数 `shellAllowMatched`：含组合/重定向/求值记号（`& | ; < >` 反引号、换行、`$()`、`%`）的命令一律不命中——`git status; rm -rf x` 的前缀匹配曾经放行过它；前缀命中后必须是词边界（`gitx` 不吃 `git` 的前缀）
- `%` 是 cmd 的求值记号（`%VAR%` 展开），与 `$()` 同罪；误伤的合法用法（如 `git log --format=%h`）转为走审批确认，是安全方向

## 修复（0.0.25 发布前审计抓到）

- **前台输出双重截断**：旧实现在"缓冲已截断的结果"上再截一次——5MB 输出的真实丢弃量被第二层标记吞掉、显示成 49 字节，模型会误以为几乎没丢；且结果可能越截越长（65698 > 65585）。改为解码后单次截断，滚动丢弃与解码膨胀的丢弃量合并进唯一标记
- **端到端测试静默跳过**：截断 e2e 用例误用批处理语法 `%%i`（`cmd /c` 命令行上下文应为 `%i`），命令秒退、输出仅 52 字节，测试从未真正跑到截断路径
- **search/目录树被自定义输出目录淹没**：并入工作区 `.gitignore` 顶层目录条目（`out/`、`target/` 这类不再出现在结果里；glob/路径式条目保守跳过）
- **测试失败聚合（轻量形态）**：模型跑的 `go test` / `go build` 失败卡折叠时也报"N 处可点位置"，不必逐卡展开翻输出
