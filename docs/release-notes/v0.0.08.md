# tiancode v0.0.08

修复版：问答答复后永久"运行中"（实机截图复现的卡死）。

## 问题（用户截图复现）

上传图片 + "这是什么" → 模型提问（问答卡）→ 你回复"三级吊装作业许可证" →
轮次卡在"运行中"38 分钟，无任何后续输出或错误。

## 根因（两层叠加）

1. **看门狗"一次性豁免"语义缺陷**：零事件看门狗本该在"90 秒无任何数据"时自动
   中断。但等待你答复期间被记为"有活动"（防止等待时被误杀），而你答复后的
   **下一张工具卡又刷新了这个标志**——此后上游黑洞（带图请求挂在 ss2a 中转上）
   再也没有任何层能收束轮次
2. **流层空闲看门狗管不到建流阶段**：HTTP 请求发出后连响应头都没回来时，流层
   的 60 秒空闲看门狗还没开始计时

## 修复：看门狗语义重写（滑动窗口 + 挂起判定）

- **任何可见活动 = 刷新计时起点**（不再是一次性豁免）：流式增量、工具卡、
  任务清单每出现一次，90 秒窗口就重新计时
- **等待审批/答复 = 挂起判定**：你思考多久都不会被误杀
- **答复返回 = 重新计时**：之后的推理黑洞在 90 秒内照常收束，给出明确的
  "响应超时"错误
- 端到端回归测试完整复现你截图的场景：上游第一轮返回提问 → 自动答复 →
  第二轮请求黑洞——修复前测试永久挂起（复现实机卡死），修复后 2 秒内收束
  并给出可读错误

## 说明

带图请求挂起本身是上游中转（ss2a 对 grok-4.7 的图像请求）的行为；应用层现在
会在 90 秒内给出明确超时错误而不是无限转圈。若带图请求持续超时，建议换渠道或
对该渠道关闭图片附件。
