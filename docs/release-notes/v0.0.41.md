# tiancode v0.0.41

编程能力三连：子代理、历史压缩、prompt cache。目标只有一个——让模型在长任务里保持"脑子清醒、花钱更少"。

## 子代理（task 工具）

- 模型可以派生**只读子代理**去做独立调研（翻代码、搜索、读文档），子代理在自己的上下文里消化几十次中间读取，只把最终报告交还主对话——主上下文不再被探索垃圾填满
- 写路径**结构性排除**：子代理工具集经只读闸门包装（fs 只放行读取类 action），没有 shell/browser/task（不递归）；task 在只读白名单里，多个调研任务可 fan-out 并行
- 隔离：子代理账本建在临时目录、跑完即删；主轮取消随时传播；单任务 15 分钟硬超时

## 历史压缩（compaction）

- 折叠到底仍超上下文预算时，不再直接报"本轮装不下"：把旧轮次的**对话叙事**摘要成一段【历史摘要】续传上下文，保留最近 3 轮全文后继续干活
- 纪律不变（0.0.09 用户裁决）：LLM 摘要只碰对话叙事，工具输出仍走确定性单行——摘要模型绝不经手行号与报错
- 压缩事件落账本（只追加，原文永不丢）；摘要失败或压缩后仍超 → 回退原有的明确超限错误

## Prompt cache（Anthropic 协议）

- Anthropic 适配器在 system 块与最后一条消息打 `cache_control`：tools+system 稳定前缀与整段对话历史逐段入缓存，下一轮按缓存价读取（成本与首 token 延迟显著下降）
- OpenAI 兼容协议依赖上游自动前缀缓存，不发送标记；内核此前已保证 system 前缀逐字稳定，本次把它变成真实收益
