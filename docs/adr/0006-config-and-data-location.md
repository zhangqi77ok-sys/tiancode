# ADR-0006：配置来源与数据位置（安装版可用性的根因修复）

日期：2026-09-23 ｜ 状态：已接受

## 背景

M5 安装包实证暴露致命缺陷：安装后从开始菜单启动，进程**秒退（exit=1）且无任何提示**。
复现证据：

```
install exit : 0
从开始菜单启动（无环境变量）: still running: False / exit code: 1
```

三条根因：

1. 配置只来自环境变量——安装版从开始菜单启动没有 env；
2. 失败走 `println`，而应用以 `-H windowsgui` 构建，无控制台可看 → 用户"点开没反应"；
3. `DataDir="data"`、`WorkDir="."` 是相对路径 → 会落在安装目录/启动目录，
   agent 的文件与命令操作范围错位。

## 决策

1. **配置以用户级文件为主，环境变量为覆盖**：
   - 主来源：`%APPDATA%\tiancode\config.json`（字段 baseUrl / apiKey / model / workspace）；
   - 覆盖：`TIANCODE_*` 环境变量优先级更高（开发与脚本化部署便利）；
   - 首次运行（文件不存在）：生成模板并弹出指引对话框，明确告知路径与必填字段，**绝不静默退出**。
2. **数据目录固定用户级**：会话账本 → `%APPDATA%\tiancode\sessions`（与安装目录解耦，
   卸载不删用户数据）。
3. **启动期错误必须可见**：壳层 `NotifyError` 弹系统消息框 + 追加
   `%APPDATA%\tiancode\tiancode.log`（排障）。
4. 安装器快捷方式工作目录 → 用户主目录（不再指向安装目录）。

## 后果

- 安装版开箱可解释：要么正常启动，要么明确告知"填哪个文件的哪几个字段"；
- 卸载保留用户配置与会话（符合直觉：卸载软件 ≠ 删数据）；
- 配置文件含明文密钥但仅存本机用户目录（0600 权限）；后续如需要可引入 DPAPI 加密
  （legacy 已有 `secret_windows.go` 先例，属独立事项）。
- 契约 C-CFG-1~6 锁定上述行为（文件不存在/解析失败/模板不覆盖/env 覆盖/目录位置）。
