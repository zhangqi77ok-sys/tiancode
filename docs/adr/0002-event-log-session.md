# ADR-0002：会话持久化采用事件追加账本（JSONL）而非全量 JSON 重写

日期：2026-09-23 ｜ 状态：已接受

## 背景

旧实现（`internal/session/store.go`）每条消息对 JSON 文件做"读-改-写全量重写"：

- Windows 下 `os.Rename` 覆盖冲突时报错，注释承诺的"备份式替换"从未实现（store.go:399-402）；
- 上层 `_ =` 静默吞错（app_chat.go:282/503），丢消息用户无感；
- 助手消息仅整轮结束落盘，中途崩溃丢整轮回答。

## 决策

会话以**追加式 JSONL 事件账本**持久化（参照 dsh-java SessionLog 事件溯源）：

- 每事件一行 JSON，追加 + fsync，成功后才推进内存状态（write-ahead，账本即事实源）；
- 崩溃恢复 = 顺序重放到最后一个完整事件；尾部半行（写入中断）直接截断；
- 快照/索引类需求用 temp+Sync+Rename+**备份式替换回退**（根治 Windows rename 冲突）；
- 持久化错误一律上抛 UI（配合守卫 R2）。

## 后果

- 最坏情况从"丢任意消息"降级为"丢最后一个未完成事件"，恢复语义可测（C-SES-3/6）；
- 长会话重放成本 O(n)，可接受（个人工具会话量级）；后续如需可加索引文件，不影响账本格式；
- 事件 Kind 字符串进入持久化格式，**一经发布不得改名**（改名为破坏性变更，需迁移方案）。
